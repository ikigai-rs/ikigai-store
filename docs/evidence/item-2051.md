# Shared nesting-check migration blocked by existing tests

The duplicate pre-parse scanners exist in `src/depth.rs`, but replacing the
format dispatch with ikigai-rdf 0.2.6 does not preserve the existing tests.
Per item #2051, the migration was stopped and the attempted source and dependency
changes were reverted. No existing tests were changed.

## Reproduction

On the original implementation, all 13 depth unit tests pass with:

```sh
cargo test --features rdf-12 --lib depth::
cargo test --features rdf-12 --test triple_term_nesting --test triple_term_growth
```

For the experiment, add `ikigai-rdf = "=0.2.6"`, alias `MAX_RDF_NESTING`
to `ikigai_rdf::MAX_TURTLE_NESTING`, and replace only the document dispatcher:

```rust
match format {
    RdfFormat::Turtle | RdfFormat::TriG | RdfFormat::NTriples | RdfFormat::NQuads =>
        ikigai_rdf::check_turtle_nesting(&String::from_utf8_lossy(text), arg),
    RdfFormat::RdfXml => ikigai_rdf::check_rdfxml_nesting(text, arg),
    // Keep the existing InvalidArgument refusal for other formats.
    other => /* existing unsupported-format refusal */,
}
```

Leaving the old private scanners temporarily in place isolates the dispatch
behavior from scanner deletion. They are no longer called by the document
check. The stored-term invariant still uses the original scanner.

The same commands then produce 10 passing and 3 failing depth unit tests,
5 passing growth tests, and 4 passing and 2 failing nesting tests.

## Cases that differ

- `nesting_after_a_string_or_iri_is_still_counted`: N-Triples input
  `<urn:a> <urn:q> 'x . <urn:a> <urn:p> {over} . # '` where `{over}` is
  65 nested `<<( <urn:s> <urn:p> ... )>>` terms. The store refuses it;
  the shared Turtle scanner treats the single quote as opening a string and
  accepts it. The test also covers a distinct N-Triples long-quote reading.
- `rdfxml_that_is_not_utf8_is_refused`: `<r/>` encoded as UTF-16LE without
  a BOM. The store refuses it; the shared XML check returns success.
- `rdfxml_counts_parse_type_triple_elements`: 200 nested property elements
  carrying `rdf:parseType="Resource"`. The store accepts it; the shared XML
  check counts every `parseType` attribute and refuses it. This behavior is
  explicitly documented by ikigai-rdf 0.2.6.
- `one_past_the_bound_is_refused_in_every_syntax` and
  `three_thousand_nested_triple_terms_are_refused_in_every_syntax_and_abort_nothing`:
  refusal wording contains `MAX_TURTLE_NESTING` instead of the store's
  `MAX_RDF_NESTING`, failing the unchanged assertions.

The minimum-version premise also needs further investigation before a future
migration: the published 0.2.5 `src/lib.rs` already publicly re-exports all
three checks and `MAX_TURTLE_NESTING`. The experiment deliberately pins 0.2.6
to test the release named by the item; it does not assert that 0.2.6 is the
true minimum.

CI on this evidence-only PR validates the retained implementation and the
unchanged tests. It does not establish compatibility of the proposed migration.
The migration remains incomplete pending resolution of these cases.
